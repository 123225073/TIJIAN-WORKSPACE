# 统一 Agent 与写作方法

用户面对一个工作助手。问答、选题、写作、身份访谈是它按需求使用的方法，不需要在前台选择多个角色。

当前实现是**有明确边界的工作流助手**。模型识别需求，程序检索本地资料、组织写作或准备媒体方案。它没有 Codex / Claude Code 式的终端、文件编辑、任意 API 工具调用循环；复制一段系统提示词也不能产生这些能力。

## 在哪里配置

管理员打开后台“提示词与 Skills”（`admin.html#skills`），或工作台“设置 → 系统能力”。

| 层次 | 维护入口 | 作用 |
| --- | --- | --- |
| 统一基础提示词 | 统一 Agent | 定义一个助手的目标、表达、主动性与实际能力边界 |
| 任务方法 | 任务方法 → 平台写作（既有自定义名称可能仍为“内容创作”）、问答与资料引用等 | 补充对应任务的专业要求，保留旧配置和历史版本 |
| Skills | Skills 方法库 | 发布的适用文本方法自动参与请求；草稿、停用、已删除的方法不参与 |
| 本次输入 | 对话或创作表单 | 平台、创作要求、字数、所选 IP、品牌、资料和原稿 |
| 固定约束 | 程序 | 权限边界、返回格式、必要字段及归属/版本检查 |

提示词组合为：程序固定边界 + 统一基础提示词 + 本次任务方法 + 启用 Skills + 输出格式约束。用户要求、IP 和资料作为单独的请求数据传入。

新增基础提示词采用默认值与已有配置按 ID 合并的方式，无数据库覆盖迁移。原 `role:writing` 是平台写作任务方法，其自定义 v2 正文、发布状态与历史保留。只有管理员明确保存或恢复默认才会改变它。

## Skills 能做什么

后台 Skills 当前是**文本方法**，程序把适用且已发布的正文加入系统提示词。模型可以据此调整叙事、标题、封面建议或检查表达；它不会因此执行 Skill 内的脚本、安装依赖、访问网页或发布内容。适用“统一助手”或“所有任务”的 Skill 会参与所有任务，写作专用 Skill 只参与写作。

内置公众号方法包括读者与传播写作、场景叙事、标题与封面、Humanizer 中文去 AI 味。它们有明确平台适用说明。小红书、口播和朋友圈按自己的内容形态写，不强套公众号目录。只停用不需要的方法，不删除正在使用的问答、核查、知识整理等配置。

## 两种生成入口

| 入口 | 实际路径与输入 |
| --- | --- |
| 统一对话 | `jobs.task_turn(mode=auto) → assistant_workspace.turn`：识别需求，按本次范围检索已保存资料，结合 IP、历史对话及当前人工底稿，为各平台分别生成；媒体先准备方案，由界面确认后生成 |
| 文案表单 / 一站式中的文案工具 | `workflows → creation.generate`：直接使用创作要求、形式、目标字数及明确选择的 IP、品牌、资料；不自动把无关个人记忆带进稿件 |
| 一站式按选题生成平台交付稿 | `topics.delivery_generate`：读取选题的角度、受众、IP、参考资料和当前交付稿，采用相同 `writing` 任务方法和启用 Skills；固定的字段校验、图片保护、长度检查继续由该流程负责 |

对话、文案工具和平台交付稿现在共用 `writing_methods.writing_request`。共同系统方法生效，区别是对话需要先识别需求，表单已把任务参数明确给出；输出格式随编辑器要求分别为结构化平台栏目或可编辑 Markdown。提示词不是只把用户那一句要求丢给模型。

对话中的明确字数会进入结构化请求；“600 字以内”会记录为上限。表单显式字数控件优先，否则采用创作要求中的字数或公众号默认值。数字相近不能作为已遵守篇幅的证明，真实模型输出仍需按实际成品判断。

## 一篇好文章靠什么控制

“任务方法 → 平台写作”（既有自定义名称可能仍为“内容创作”）控制通用写作要求，启用的写作 Skills 控制叙事、标题、封面等细节，本次平台、字数和 IP 控制实际风格。公众号默认围绕一个读者问题建立阅读主线，有具体开头、自然推进和回扣结尾；清单、说明书和报告按用户指定结构处理。

故事与情绪必须有真实素材或明确标识的假设场景，不能编造作者经历、客户对话和事故。标题兑现正文，封面建议围绕一个核心问题。方法能改善可读性与传播动机，不能保证爆款。

## 留痕与验证边界

统一对话的基础及各分支方法在提交、排队前冻结。管理员后续修改影响下一次请求，已提交任务继续使用原配置。文案工具也冻结所选 IP、品牌、资料内容与版本。

对话和文案工具的成品保存 `capabilities` 与 `request_snapshot`：基础/任务/Skill 的 ID 与版本、配置哈希、实际系统请求哈希、输入哈希、平台、字数和约束类型。任务记录只保存配置元数据，不保存内部方法全文。后台预览可查看已保存的组合，不调用模型；具体会话资料、程序输出协议仍由各入口补充。

相关模块：`backend/capabilities.py`（组合与版本）、`backend/assistant_workspace.py`（统一对话）、`backend/creation.py`（文案工具）、`backend/writing_methods.py`（共享约束与请求）、`backend/jobs.py`（固定边界）、`backend/gateway.py`（模型协议）。模型网关当前只发送 `messages/input`，没有注册模型工具。

本次组合测试捕获实际请求，检查自定义 v2 保留、已发布/停用 Skills、排队版本、个人偏好、字数和资料约束。页面测试检查后台编辑、预览与不同窗口宽度。隔离测试替代模型用于验证程序，不构成真实模型文风或爆款效果验收。

设计对照仅使用公开官方说明：[Codex 的分层项目指令](https://developers.openai.com/codex/guides/agents-md)、[Claude 的工具调用与应用执行循环](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)。本次采用分层指令、显式执行边界与可追溯输入的原则，没有复制私有系统提示词或扩大工具权限。
