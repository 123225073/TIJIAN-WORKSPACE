# 0.9.0 知识工作台交付与验收

日期：2026-09-18。

## 需求与结果

| 本轮需求 | 已实现的行为 | 验证 |
|---|---|---|
| 原始资料直接提问 | 导入后可选入回答，自动查找也能检索未提炼原文 | 后端用例、实际模型请求检查 |
| 减少确认负担 | 普通 Wiki/明确个人记忆自动保存；冲突、不确定及手动编辑保护进入需核对 | 后端与桌面页面验证 |
| 文件夹管理 | 原文、Wiki、记忆的多级文件夹、重命名、上级调整、全选/多选和批量移动 | API、界面、越权/循环/非空删除约束 |
| 内部连接与选择范围 | 九个内部资料模块，文件夹/条目选择，全选、清空、范围和草稿保存 | 重新加载页面后恢复；检查模型实收上下文没有范围外资料 |
| Wiki 优先，必要时看原文 | 分段全文检索、AI 同义扩展、来源追溯、字符预算及未带入提示 | 长文后半段、同义词、无答案、停用/删除/更新后的排除 |
| 对话长期记忆 | 只提取用户发言，逐字依据，不接受助手生成内容作为本人事实 | 假设角色进入需核对，已删除记忆不重建 |
| 夜间整理与独立模型 | 可设时间、模型、调用上限，增量检查点、启动补跑、中断续跑 | 时钟模拟、重复触发、启停与分批验证 |
| 保留个人资料与原入口 | 新版使用原数据目录，桌面快捷方式指向 0.9.0 | 实际启动与数据库内容摘要比对 |

## 已运行的验证

- `npm test`：96 项通过；2 条来自测试依赖的弃用提示，不影响结果。
- `npm run build`：TypeScript 和 Vite 构建通过。
- `node scripts/test-library.mjs`：文件夹、新版自动整理、引用选择、草稿恢复、实际上下文、整理设置和小窗口通过。
- `node scripts/test-knowledge.mjs`：旧版候选兼容、审阅保存、编辑、重复/空结果/失败、原文缺失预检、回收站恢复通过。此脚本用旧提炼 API 创建历史候选，普通新版流程由上一个脚本验证。
- `node scripts/test-page-scopes.mjs`：首页、雷达、对标页面范围回归通过。
- `npm run package`：0.9.0 Windows 目录包构建成功。
- `node scripts/check-desktop-release.mjs`：实际打包应用启动通过；打包后的 SQLite 全文检索找到超过第15000字符的证据，文件夹与夜间设置 API 可用，原系统能力与浏览器桥接入口仍存在。

## 真实模型验证

在独立测试工作区中，使用已配置的 gpt-5.5 和实时获取的 WorkBuddy 官方记忆说明，完成：原文 → 自动 Wiki → 用户明确发言 → 自动个人记忆 → 混合检索 → 带来源回答。

结果：整理出2条 Wiki、2条个人记忆，另有1条不确定信息进入需核对。实际回答使用了 Wiki、原文和记忆，正确说明官方文档中的夜间频率及用户可以编辑、删除、关闭。此为单个真实场景验证，不代表全面检索准确率评测。

隔离页面测试使用明确的模型夹具，真实模型测试与之分开；没有把夹具输出当作真实 AI 成果。测试业务记录没有写入用户的资料库。

## 本机交付

- 桌面“梯见工作台”快捷方式已更新为 `release/0.9.0/win-unpacked/梯见工作台.exe`。
- 项目内“启动梯见.cmd”优先启动 0.9.0，旧版本目录保留。
- 通过桌面快捷方式实际启动，新服务返回版本0.9.0、SQLite + Markdown 持久化。
- 启动前后19条既有原文、知识、记忆、作品、对话和身份记录均保留；内容、来源引用、归档状态及分类摘要没有变化，工作区和自动整理设置未被修改。
- 新版夜间整理尚未替用户开启；在“设置中心 → 记忆与 Wiki”选择模型并保存启用后生效。

## 实际限制

本次交付是本机 Windows 目录包，未签名，不是自动升级或对外发布。退出程序或电脑休眠时不运行定时整理。文件夹目前是软件内分类，不会搬移原文件。

本版是轻量全文检索 + AI 查询扩展 + 主题 Wiki；没有向量模型、独立重排服务、全库自动冲突裁决、外部 IM 或 MCP。正文定位为字符区间，不能冒充 PDF 页码。Wiki 内容仍需以来源为准。

完整设计与使用方式见[个人知识工作台：设计与使用](个人知识工作台-设计与使用.md)。
