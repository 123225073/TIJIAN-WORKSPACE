# 内容矩阵的平台写作调用

本次修复的是写作实际调用，不只是界面上的平台名称。此前官网、知乎、百家号、今日头条、简书、搜狐号的内容形式没有进入写作平台映射，专属方法筛选会退回 `general`。现在八个平台均有明确映射，后台可以分别维护、预览和停用专属方法。

## 实际链路

用户选择平台 → 使用已保存母版版本与该平台内容形式 → 文案生成接口 → 冻结后台已发布方法 → 按平台筛选方法 → 向模型提交本次发布平台、篇幅、母版资料、IP和专属写作方法 → 分别保存平台稿件与请求版本记录。

各平台共享母版中的事实、数据和范围，重新组织标题、开场、结构、段落、语气和结尾。母版正文作为资料传入，不执行其中的指令。后台“提示词与 Skills”中，八个“平台原生写作”项目分别对应八个平台；既有管理员编辑过的项目保持原样，不迁移或覆盖实际账号配置。管理员保存修改后影响后续请求，已提交任务继续使用提交时冻结的方法版本。

## 默认编辑方向

| 平台 | 写作重点 | 避免 |
| --- | --- | --- |
| 官网 / 品牌博客 | 明确答案、适用场景、方案/服务边界、相关常见问题 | 虚构品牌能力、搜索排名承诺 |
| 微信公众号 | 完整阅读主线、鲜明观点、手机短段、自然论证 | 机械目录、无信息小标题 |
| 小红书 | 具体人群与场景、实用清单、短段、适量emoji、相关话题 | 公众号缩写、虚构亲历、表情堆砌 |
| 知乎 | 开篇直接作答、依据、条件、例外和因果解释 | 软广、无依据权威人设 |
| 百家号 | 可检索的问题标题、通俗知识解释与核对要点 | 伪装最新新闻、堆关键词 |
| 今日头条 | 具体疑问或观察开场、明快节奏、实用判断 | 悬而不答、煽动冲突 |
| 简书 | 观察、思考、取舍与认识的完整线索 | 编造作者经历、强行抒情 |
| 搜狐号 | 行业问题解读、背景、事实、分析与影响 | 虚构消息人士、夸大行业影响 |

小红书默认约500字时使用3至6个承担视觉分层作用的emoji，结尾3至5个相关话题。这些数量是本工具的编辑建议，不是平台强制要求或算法结论。用户要求、管理员文风和已确认IP可以调整；不强行改写用户已保存的正文。

## 已验证与边界

- 离线使用隔离数据库和拦截模型边界的测试，逐个平台通过真实矩阵生成接口验证：正确平台、相同母版事实、专属Skill版本、排除其他平台专属方法、分渠道结果保存、后台专属预览。
- 验证管理员自定义方法保留、已提交任务版本冻结、停用的方法不被程序重新注入。
- 相关矩阵、后台能力、口播格式回归共14项通过。测试返回内容明确为固定离线样例，未调用收费模型，也不把样例当作模型质量证据。
- 提示词改善生成方向，不能保证每次模型输出完全合格、传播效果或平台审核通过。真实成稿质量、平台账号权限与实际发布属于独立验收范围。
