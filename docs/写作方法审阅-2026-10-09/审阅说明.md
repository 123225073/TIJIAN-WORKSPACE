# 写作方法审阅与精简

本次范围为写作文本配置。读源码与安装版数据库确认实际配置后，对已有写作任务方法进行修订、将 Humanizer 改为中文精简规则，并停用一项重复的公众号方法。保留原配置历史；不扩展 Agent 工具权限。

## 调用与清理判断

- 统一对话自动分类只有 chat/profile/text/image/video，不能据此认定后台其他方法无用。
- 内容分析用于独立对标分析；选题策划用于候选选题生成；品牌访谈、事实核查、知识整理都有调用入口，继续保留。
- 资料研究仍被通用任务接口和个人偏好选项支持，但不在当前统一对话的独立自动分支中。宜标为兼容/高级入口，不能直接删除在用配置。
- `skill:writing`（公众号写作）与 `skill:wechat-editor`（公众号读者与传播写作）默认正文同为 `ARTICLE_METHOD`，无用户覆盖时会重复进入写作请求。本次保留前者，停用后者；需要时可恢复。
- Humanizer 原始文件有 32,309 个字符，其中大量英文例子随所有平台写作一起进入请求。精简中文适配版保留声线、信息增量、自然节奏、事实保护和交付检查。原始全文留在配置历史及本地 vendor 文件，不删除上游来源。

## 普通用户可以调整什么

更正：旧组件中存在“设置 → AI 与创作偏好 → 个人工作偏好”，但当前在用路由未挂载该组件，账户菜单也没有入口。当前前台实际可用的是“我的 IP → 编辑档案 → 表达方式”。后台 `/api/prompts` 按用户保存偏好，`capabilities.snapshot(purpose, owner)` 可读取它，但后台能力存在不等于页面已接通。

全局任务方法和 Skills 方法库的编辑、Markdown 导入仅限管理员。普通用户目前没有个人 Skills 的创建、导入、启停与绑定界面，但并非只能靠知识库影响输出。

知识库保存事实素材与参考样文；身份的表达方式字段控制当前身份声线；账户级个人偏好的后端和旧组件仍保留，但尚无在用入口；管理员方法定义公共流程。

个人写作偏好示例：

> 默认用同行之间聊天的语气，正文围绕一个问题连贯展开。需要编号清单时才分点。参考我本次选择的旧文学习表达，旧文的经历和数字不能当作当前文章的事实。具体平台、字数和本轮要求优先。

## 原 v2 的审阅结论

保留：用户参数优先、适应平台、标题兑现正文、事实约束、内部成稿与校对。

优化：

- 角色履历、人格和能力介绍占用了篇幅，可改成明确的任务动作与验收要求。
- `target_audience` 写成自媒体创作者、IP 运营者，容易与本次文章的终端读者混淆。改为从本次输入/IP 确定文章读者。
- “抓人的开头、层次清晰、观点深度”等方向正确，但缺少可执行标准。补充唯一主问题、段落信息增量、标题兑现、场景来源和通读修订。
- “缺关键信息先询问”用于对话阶段合适，但文案表单已经进入生成流程，若模型仅回提问会被保存为稿件。写作方法改为缩小事实结论或明确待补信息，不补造事实；前置需求澄清仍由统一对话负责。
- 结构化写作指组织内容，不等于每篇必须编号、三段式或目录式。保留平台与用户指定形式的区别。

## 内容应该放在哪里

| 内容 | 放置位置 |
| --- | --- |
| 任务目标、输入怎么解释、平台适配、事实与字数检查、最终交付原则 | 平台写作任务方法 |
| 公众号叙事、标题和封面、中文语言修订、某个平台的具体技巧与示例 | Skills 方法库 |
| 本人的用词、表达偏好、默认篇幅、喜欢的声线 | 个人工作偏好／IP 档案 |
| 产品事实、客户确认经历、原始资料、本人文章样本 | 知识库，并在本次请求中选入 |
| JSON 栏目、权限、归属、版本与写入校验 | 程序 |

目前仍按任务类型筛选 Skills，平台限制主要靠方法正文和任务输入表达；没有新增程序级平台筛选。本次精简规则不等于接入自主联网或脚本执行。

## 首轮更新与后续更正

以下为首轮精简记录。用户指出 Humanizer 515 字版可能损失效果后，已转为完整中文适配；当前版本、二十六类覆盖及个人偏好入口的核实见 `docs/中文方法库-2026-10-09/审阅与适配说明.md`。不能把首轮记录当作最新版。

已更新安装版的本地配置，三个项目分别为：`role:writing` v3（启用）、`skill:humanizer` v2（启用）、`skill:wechat-editor` v2（停用）。方法在后续请求读取时生效；已经提交并冻结的任务保持其原有版本。

配置验证通过：原写作 v2 保留在历史；Humanizer 原始全文保留；资料研究 v4 及其他已有覆盖项不变；其余 11 类任务的方法组合哈希不变；公众号文章、小红书文案、口播脚本的请求组合包含新的任务方法和语言修订规则。Agent 与文案入口继续共用 `writing` 方法。

公共写作方法组合由 37,107 字符减少到 3,910 字符。这是方法组合正文长度，不是整个模型请求长度；具体请求还会加入程序要求、本次资料、IP、历史和用户输入。

原配置及验证记录保存在 `.runtime/side-writing-review-20261009-7d6b0f08/`。本次未修改应用源码、模型连接、账号、知识库或其他任务配置，没有调用付费模型。

这类检查只能证明配置和调用逻辑正确，不能证明公众号成品质量已经提升。成品比较应使用相同模型、相同资料、相同参数，对旧版和新版各生成以下类型的稿件：

1. 公众号科普，600 字以内，无本人案例：检查开头、阅读主线、事实保护与目录感。
2. 公众号观点文，提供一段真实客户素材和本人样文：检查作者声线、判断与叙事。
3. 小红书或口播稿：检查是否误套公众号结构、是否自然可读／可说。
4. 用户明确要求编号清单：检查方法是否尊重内容形式。

联网搜索增加新资料，Skills 提供写作方法，真实模型、本人样文与真实素材共同决定成品。开源方法数量不能作为质量验收证据。
