# 工作成果与创作流程联动

## 使用方式

公众号成果可继续编辑。正文在独立区域滚动，插图操作留在正文区域顶部；选择插入位置后，素材或生成结果回到该位置。

AI 安排的配图提示词属于制作计划。计划折叠显示，阅读预览和公众号发布稿不含这些文字。为某一计划生成图片后，只替换对应计划；失败时保留，正文被修改时要求重新核对，图片留在素材库。

完成文稿后点击“保存并进入平台准备”，当前保存版本的标题、正文、摘要、封面和排版带入一件一站式作品，并打开相应发布稿。这里仍是本地准备，实际发布需另行明确操作。相同文稿版本再次点击会打开原作品；文稿更新后再次带入产生新版本作品，避免覆盖已经人工修改的发布稿。作品内可返回原对话；原稿和发布稿各自继续编辑。

## 成果如何对应功能

| 对话成果 | 保存目标 | 使用入口 |
| --- | --- | --- |
| IP 定位方案 | 待确认的 IP 候选；确认后新增或更新一份个人档案 | 我的 IP |
| 选题建议 | 待确认候选；用户筛选后加入选题库 | 选题库，继续创作 |
| 公众号、朋友圈、小红书等文案 | 各平台独立的文稿，保存标题、正文及适用栏目 | 继续编辑、导出；公众号可进入一站式平台准备 |
| 视频号、抖音文稿 | 标题、发布描述、纯口播稿、分镜分别保存 | 一站式平台准备、数字人口播制作 |
| 图片、视频方案 | 可编辑的生成草稿；确认生成后才产生素材 | 完整制作工具、素材库 |

AI 先根据本轮要求、历史上下文识别成果类型，并返回限定格式。程序检查类型、平台、当前账号、目标及版本，再调用该类成果的保存逻辑。界面根据实际保存的成果展示相应编辑器与下一步按钮。普通聊天不会因为提到某功能就写入资产，模型回复“已保存”也不能替代真实数据库写入。

这种联动由明确的类型和实际记录关系实现，不依赖模型临时猜测页面或任意执行工具。现有模型负责理解和创作即可；资产归属、确认、版本及发布边界交给程序。另换一个决策模型不能解决缺失的数据关联与入口。

## 保留与追溯

- 对话文稿、制作计划、图片素材、作品与平台稿都有各自记录；不拿上一件作品或最新一份稿件自动顶替。
- 一次带入的选题、文稿副本、封面副本、作品及发布草稿一起保存，失败不留下半件作品。
- 转入记录保留原文稿编号和版本。生成期间改稿、过期页面和越权请求都不能静默覆盖当前内容。
- 只按明确标记识别制作块；文章正常讨论提示词或图片时保留原文。
