# 安装、运行与打包

适用版本：0.13.0，当前桌面交付目标为 Windows 10/11 x64。macOS、Linux 的桌面脚本未适配，不能按 Windows 验收结果推定可用。

## 从 GitHub 获取源码

准备 Git、Node.js 22 LTS（建议 22.12 或更高）与 Python 3.12，使用 PowerShell：

```powershell
git clone https://github.com/123225073/TIJIAN-WORKSPACE.git
cd TIJIAN-WORKSPACE
npm ci
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm run build
npm run desktop
```

如果电脑不提供 `py` 启动器，可用指向 Python 3.12 的 `python` 替换 `py -3.12`。无需激活虚拟环境，后续命令直接指定其解释器。

运行所需的 Easel 组件子集已经随仓库提供，不需要递归初始化子模块或启动上游 Agent。微信读书适配器也不依赖启动独立 we-mp-rss 服务器。

`npm run desktop` 启动 Electron，并自动寻找空闲本机端口运行后端。它读取已构建的界面，所以首次运行与界面改动后要执行 `npm run build`。

## 首次配置

1. 创建本机账户。首个账户为本机管理员，不带有预设密码或演示凭据。
2. 选择专用空目录作为工作区，避免选整个磁盘或已有杂乱目录。
3. 导入一份自己的文稿，保存后重新打开，确认本地读写正常。
4. 需要 AI 时，打开账户菜单 → 管理后台 → 模型与连接，填写自己的服务配置。
5. 依次发现模型、实际测试、上架，再设置功能绑定。模型测试可能产生服务商费用。
6. 公众号订阅按[专门说明](公众号采集与费用.md)连接微信读书；次幂按需配置，不是首次启动必填项。

## 浏览器开发模式

后端终端：

```powershell
.\.venv\Scripts\python.exe -m backend.run
```

另一终端：

```powershell
npm run dev
```

打开 `http://127.0.0.1:5178`。Vite 将 `/api` 转发到本机 `18786` 端口。此模式适合界面开发；桌面登录、文件夹选择、微信验证等 Electron 桥接能力须在桌面版验证。

不要把开发端口或后端直接暴露到公网。当前没有完成云端生产部署、多租户安全和远程任务服务。

## 测试

```powershell
npm test
npm run build
node scripts/test-wechat-list.cjs
node scripts/test-platform-sessions.cjs
node scripts/test-remember.cjs
node scripts/test-dates.mjs
```

`npm test` 使用独立临时数据和测试夹具，不读取正式模型/次幂连接。测试请求的模拟返回仅用于验证程序行为。

构建后可运行隔离的桌面流程：

```powershell
node scripts/test-free-subscription.mjs
node scripts/test-paid-body.mjs
```

这些测试模拟上游平台及凭据，不会实际调用付费次幂接口。真实扫码登录、目标公众号覆盖率及持续新文获取需要另行实测。

## 构建 Windows 桌面目录包

```powershell
npm run package
```

命令依次进行前端构建、PyInstaller 后端打包和 Electron 目录包生成。首次执行需要下载 Electron 等构建依赖。

输出：`release/0.7.0/win-unpacked/梯见工作台.exe`。复制或移动时保留整个 `win-unpacked` 目录及 `resources`，不要只拿 EXE。当前命令使用 `--dir`，没有生成已签名的安装程序。

打包后可以运行：

```powershell
node scripts/check-desktop-release.mjs
```

它在独立数据目录启动打包应用检查版本与桥接能力。`scripts/check-release.py` 还会访问真实公网 RSS，属于联网检查，不是离线单元测试。

根目录 `启动梯见.cmd` 优先打开当前版本目录包；没有目录包时尝试开发版 Electron。初次克隆仍需先安装依赖并构建。GitHub 仓库本身不附带本机生成的目录包。

## 升级与数据

升级前使用设置里的备份导出，并保留原工作区。完全退出旧实例后再运行新版；单实例机制可能把第二次启动切回仍在运行的旧版。

开发版使用项目 `.runtime/`；打包版使用 Electron 用户数据目录下的 `data/`。它们不是同一个数据库。打包版常见位置是 `%APPDATA%/elevator-workbench/data`，实际以 Electron `userData` 为准。工作区则使用用户在软件中选择的路径。

不要用空数据库覆盖原数据库，也不要通过上传整个用户数据目录分享配置。备份和恢复边界见[技术架构与数据说明](技术架构与数据.md)。

## 常见问题

| 现象 | 检查方式 |
|---|---|
| `py` 或 Node 找不到 | 安装对应运行时并重新打开终端；核对 PATH |
| 提示本地服务无法启动 | 确认 Python 虚拟环境和依赖；打包版确认 resources 完整 |
| 界面空白或显示旧内容 | 重新构建；关闭旧实例再启动，不混用历史 release 目录 |
| 找不到免费订阅按钮 | 使用 0.6.0，选择平台为公众号的对标账号，进入文章库与订阅 |
| 微信读书已登录仍无法保存 | 返回工作台点击保存连接；账号需在新版专用窗口登录 |
| 模型不存在或无权调用 | 核对自己的 Base URL、协议、额度及模型权限，再测试并上架 |
| 导入后看不到历史资料 | 查看日期筛选是否仅选了当天，检查资料类型及回收站 |
| 正文全部失败 | 查看逐篇原因；目录成功不代表正文可访问，平台验证需在桌面窗口处理 |

程序设置限速和失败延后，但不能保证第三方平台永远可用，也不能保证账号零风险。
